| Recovery | After a damaged session index, blanket cleanup could delete the only surviving drafts. A second corrupt session could overwrite the earlier quarantine. | Cleanup owns only drafts successfully read/written during this run. Orphaned or unreadable drafts survive subsequent launches. ## Breadth of review

Architecture and ownership are coherent for this application size: AppState coordinates per-document editor controllers, a pure text/search/highlighting layer, and a separate plugin policy/runtime. Profile selection, bounded file reads and draft ownership now have small shared authorities. No wholesale framework rewrite is justified.

Reviewed save/reload/termination, drafts and session restoration, encoding/EOL, edit/undo/index plumbing, search/replace, highlighting/completion, watchers, plugin manifests/grants/paths/commands/storage/panels/network, UI and the existing Ink & Phosphor contract, updater/release tooling, dependencies and CI. Permission, containment, malformed-manifest, regex and line-marker coverage from the previous pass remains in place. The application has no third-party runtime packages; the only compiler dependency used here is the pinned development-time TypeScript tool.

## Verification and limits

The isolated baseline passed 55 XCTest cases. Four newly added cases failed before their fixes: malformed UTF-8 round trip, failed plugin-write cache consistency, immediate dirty state and same-loop line indexing. The expanded suite has 74 cases, including actual JavaScript API validation, cancellation, storage failures, panel replacement, recovery ownership, profile separation, regular-file limits and shipped plugin activation. Tests use synthetic files/plugins and a stub URL protocol, never the installed app's data or live external providers.

Unsigned Debug tests, Release archive and analyzer are exercised locally on Xcode 26.6 / Swift 6.3.3. ShellCheck, actionlint, exact plugin compilation and diff checks are included. The first sandboxed XCTest invocation could not reach Apple's test manager; the explicitly approved isolated invocation succeeded. Xcode emitted ancillary AppIntents, WebKit/desktop-service and archive debug-module-cache warnings; these are retained in evidence rather than hidden. Remote CI status is recorded on the PR and the external queue report.

The current Forge runner advertises `arm64`, `ubuntu-latest`, and `docker`; no runner advertises `macos-15`. Portable plugin contracts therefore run in their own Linux job. The native macOS job remains intact and requires a matching runner; local passing tests do not turn that missing remote gate green. Runner infrastructure was not changed.

This is a code-quality pass, not installed-app acceptance or a signed release. Interactive editor behavior, VoiceOver/keyboard traversal, Finder/open-file behavior, actual update presentation and notarized distribution still need human/native acceptance. Local Xcode 26 results do not prove the Xcode 16 CI matrix or macOS 14 runtime. The plugin host still executes granted JavaScript in-process; permission checks are not an operating-system sandbox or a guarantee against a plugin that never yields. Large accepted buffers and regular-expression workloads can still be expensive. Recovery retains unknown drafts intentionally; removing recovered remnants is a user decision.

No primary source/data edits, installed-app launch, signing/notarization, publishing, production configuration change, merge or deployment were performed in this project.
